# `crontab ~/bin/crontab.txt`. Edit here (and commit) rather than editing the
# live crontab directly with `crontab -e`, so it doesn't silently drift from
# what a fresh install would recreate.
#
# NOTE (2026-09-02): a line that used to be here -
#   35 6 * * * sudo ufw allow 8200/tcp && sudo ufw allow 1900/udp
# has been removed. ufw was never actually installed on this system (the
# firewalling that exists is nftables rules managed by Tailscale itself), so
# this line has been silently failing every day since it was added. minidlna
# and Samba both work fine on the LAN without it - there's no firewall
# blocking those ports in the first place.

# Claude Code login keep-alive (2026-09-02): claude_usage_poller.py below
# reads THIS machine's own ~/.claude/.credentials.json directly - it stays
# fresh automatically only if `claude` actually runs here at least once
# within its ~8h access-token lifetime. Nobody uses `claude` interactively
# on this headless Pi, so the token was silently going stale between visits
# (last real use was 2026-09-01, causing a run of HTTP 401 warnings a day
# later). This trivial no-op prompt exists purely to touch the CLI often
# enough to keep it refreshed - well under the 8h expiry - with output kept
# to a small local log rather than stdout, so it doesn't trigger MAILTO.
0 */4 * * * cd /home/pi/home_automation && { date -Is; /usr/local/bin/claude -p "reply with just: ok"; } >> logs/claude_keepalive.log 2>&1

# Forced-subtitle scanner (see docs/superpowers/specs/2026-09-14-forced-
# subtitle-scanner-design.md). identify is weekly - new films arrive rarely,
# and already-cached files are skipped, so this only has to pick up what's
# new since last time. apply is daily and rate-limited internally
# (--max-downloads) to stay within the OpenSubtitles account's real daily
# quota (confirmed via /api/v1/infos/user on 2026-09-19: 20 downloads/day
# on this "Sub leecher" free-tier account). --max-downloads 15 here, not
# 20, deliberately leaves headroom on the same shared account for
# convert_video's own interactive per-file fetch (maybe_fetch_forced_
# subtitle) run later the same day. It's cheap day-to-day regardless of
# the count because it calls scan internally, which now only re-probes a
# file that's genuinely new/changed OR whose last check is older than
# SCAN_FRESHNESS_DAYS (default 30) - see cmd_scan's freshness check in
# forced_subs. A film stuck ambiguous/unfetched/unmatched isn't going to
# resolve differently by re-checking it daily.
0 4 * * Sun cd /home/pi/bin && ./forced_subs identify --quiet >>/home/pi/logs/forced_subs_identify_logfile 2>&1
0 5 * * * cd /home/pi/bin && ./forced_subs apply --max-downloads 15 --quiet

# Monthly deep re-probe: `scan --rehash` bypasses the freshness check above
# entirely (re-probing every non-HAS_FORCED file via convert_video) AND
# gives every previously-unresolved/ambiguous title a fresh identify
# attempt (including another shot at the title-search fallback, in case
# OpenSubtitles' own catalogue has grown since). This is the expensive,
# hours-long full-library pass - deliberately not a daily job. An hour
# after the weekly Monday reboot above so the HDD/network are settled.
#
# NOT `0 7 1-7 * Mon` - cron ORs day-of-month and day-of-week when both are
# restricted (see `man 5 crontab`'s Note), so that would fire on every day
# 1-7 of the month AND every Monday, not just the first Monday. Instead:
# run every Monday (day-of-month left as `*`, so no OR ambiguity) and let
# the command itself skip unless it's genuinely within the month's first
# 7 days.
0 7 * * Mon [ "$(date +\%-d)" -le 7 ] && cd /home/pi/bin && ./forced_subs scan --rehash --quiet >>/home/pi/logs/forced_subs_scan_logfile 2>&1

# The Pi reboots weekly (its own separate cron job) and identify's first
# full-library pass can run long enough to still be mid-run when that
# happens. identify is safe to interrupt and re-run - it caches each
# file's result as it goes (forced_subs_file_ids, written atomically) and
# skips anything already resolved - so instead of a watchdog, this just
# resumes it once after every boot. `sleep 60` gives the HDD mount and
# network time to come up first; harmless/near-instant once identify has
# actually finished the whole library, since there's nothing left to do.
@reboot sleep 60 && cd /home/pi/bin && ./forced_subs identify --quiet >>/home/pi/logs/forced_subs_identify_logfile 2>&1
